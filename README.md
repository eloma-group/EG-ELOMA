# EG Eloma — React + TypeScript

React 19 + TypeScript + Vite + React Router port of the static EG Eloma site.
Markup, copy, images, CSS (`src/site.css`) and animations are carried over unchanged.

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # outputs dist/ (every page prerendered to static HTML)
```

## Structure
- `src/pages/*.tsx` — one component per page; the file name maps to the route
  (`WebsiteDevelopment.tsx` → `/website-development`, `Home.tsx` → `/`).
- `src/components/` — `Header` (mobile menu), `Footer`, `Credentials`, `CountUp` (stat counters),
  `HeroStudio` (home "live preview" demo), `ContactForm`, `PageMeta` (title/description/canonical/JSON-LD).
- `src/blog.ts` — blog articles (title, date, category, reading time). Each article's text is in
  `src/pages/Blog<Name>.tsx`, laid out by `components/BlogPost`; the Blog page and "Related reading" lists read from here.
- `src/siteInfo.ts` — business details and `COUNTRIES` (the five country pages, their hreflang and currency).
  Pages for the US, Canada, UK and NZ pass `country` to `Header`/`Footer`, which then show the email instead of the
  Australian phone number.
- `src/hooks/useReveal.ts` — scroll reveal for `.rv` sections.
- `public/` — images, favicon, fonts, `robots.txt` (`sitemap.xml` is generated by `scripts/prerender.mjs`).

## Build & speed
`npm run build` builds the app, then `scripts/prerender.mjs` renders every route to static HTML
(`/` → `dist/index.html`, `/seo` → `dist/seo.html`), so pages paint before any JavaScript runs:
- the stylesheet is inlined into each page (no render-blocking request);
- the app script and the web fonts load after the first paint; React then hydrates the existing HTML;
- size-matched fallback fonts (`Geist Fallback` etc. in `site.css`) keep layout stable until Geist is applied
  (straight away for returning visitors, on the first click for new visitors);
- sections below the first screen use `content-visibility:auto`.

## Hosting
Azure Static Web Apps deploys automatically on every push to `main`
(`.github/workflows/azure-static-web-apps-*.yml`, routing in the generated `dist/staticwebapp.config.json`).
Other hosts are covered too: `public/.htaccess` (Apache / cPanel / Hostinger) and
`public/web.config` (IIS). Each serves `/seo` from `seo.html`, 301s old `.html` links to clean URLs and answers
unknown URLs with `404.html` ("Page not found", `src/components/NotFound.tsx`) and a 404 status.
For manual hosting, upload the contents of `dist/` to the site root.

## Contact form email
`components/ContactForm` posts to `/api/contact`, an Azure Function in `api/` (deployed with the site by the
workflow above), which emails the enquiry to connect@egeloma.com.au through Microsoft 365 (Graph `sendMail`).
It needs these Static Web App environment variables: `M365_TENANT_ID`, `M365_CLIENT_ID`, `M365_CLIENT_SECRET`
(an Entra app registration with the **Mail.Send** application permission, admin-consented), plus optional
`MAIL_FROM` / `MAIL_TO` (both default to connect@egeloma.com.au). `/api` only exists on Azure, so on
`npm run dev` the form shows its "couldn't be sent" message. Other hosts (Apache, IIS) get no API.
